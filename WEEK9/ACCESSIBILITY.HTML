Flower Diary
Website Improvements Report

This report describes the testing and improvements made to Flower Diary. It focuses on website performance, accessibility, and search engine optimization (SEO), using Google Lighthouse results as evidence.

View Final Results
01 · Introduction

About the Project

Flower Diary is a small flower-discovery website. Visitors can explore a collection of flowers, read about their meanings and care, and search for a flower by name. The design uses soft pink and lavender colors, rounded cards, and simple navigation.

Project Goals

  • Make the website load quickly and behave smoothly.
  • Make the content easier to navigate using accessible HTML features.
  • Help search engines understand the page through useful metadata.
  • Test the website and document the results with Lighthouse.
02 · Performance

Performance Testing and Improvement

The first Lighthouse run gave Flower Diary a Performance score of 82. The report also warned that Chrome extensions negatively affected the page-load test. To reduce that interference, the page was tested again in a Chrome Incognito window.

What the First Test Showed

  • First Contentful Paint (FCP): 0.2 seconds.
  • Largest Contentful Paint (LCP): 0.2 seconds.
  • Total Blocking Time (TBT): 420 milliseconds.
  • Cumulative Layout Shift (CLS): 0.

The first run's extension warning means the score of 82 should not be treated as a direct measure of the website alone. The later Incognito run achieved 100. The two runs were made under different browser conditions, so the score change should be interpreted with that limitation in mind.

03 · Accessibility

Accessibility Features

Flower Diary received an Accessibility score of 100 in the initial Lighthouse test. The page includes several features intended to make navigation and content easier to use.

Features in the HTML

  • A skip link lets visitors jump to the main content.
  • The navigation landmark has an accessible label.
  • The flower search input has a matching text label.
  • Flower emoji illustrations have accessible names.
  • Visible focus outlines help keyboard users see focus.
  • A status message is provided when no flowers match a search.

Example of the Skip Link

<a class="skip-link" href="#main">
  Skip to main content
</a>

<main id="main">
  ...
</main>

This gives keyboard users a way to move past repeated navigation links and reach the main content.

The final Lighthouse summary also showed an Accessibility score of 100. A high automated score is useful evidence, but it does not replace manual keyboard, zoom, and screen-reader testing.

04 · Search Engine Optimization

SEO Improvement

The initial SEO score was 90. Lighthouse identified one issue: the document did not have a meta description.

Change Made

A descriptive meta tag was added inside the document's head section: 

<meta name="description"
content="Discover beautiful flowers,
their meanings, and simple tips to care
for them with Flower Diary.">

This provides a short summary of the page for search engines and other systems that use page metadata.

06 · Reflection

What I Learned

  • How to use Lighthouse to test website performance, accessibility, and SEO.
  • Why metadata such as a meta description is useful.
  • How semantic HTML, labels, skip links, and focus styles support accessibility.
  • Why test conditions, including browser extensions, can affect audit results.
  • Why automated scores should be supported by manual checks.
07 · Conclusion

Conclusion

The Flower Diary project was reviewed in three areas: performance, accessibility, and SEO. The final Lighthouse report showed a score of 100 in all three selected categories. The work also highlighted the importance of checking the testing environment and combining automated audits with manual accessibility checks.

Final Lighthouse Scores: 100 / 100 / 100
